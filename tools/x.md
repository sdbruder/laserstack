# Posting on X as @laserstackphp

`tools/x` posts, replies and reads on X through
[twitter-cli](https://github.com/jackwener/twitter-cli), authenticated with the
session cookie of @laserstackphp, kept in 1Password.

Every fact about the account lives in one 1Password item, **Laser Stack X**, in
the **Private** vault:

| Field | Value |
|---|---|
| username | `laserstackphp` |
| password | generated by 1Password, never typed or written anywhere else |
| one-time password | the TOTP secret of the account |
| email | `laserstack@bruder.com.br` |
| `auth_token`, `ct0` | two text fields, the session cookie the tool posts with |
| notes | recovery codes, written when X shows them |

The email is a Google Workspace alias on a domain that stays: a mailbox you
control outlives any provider. That alias, the TOTP secret and the recovery
codes are the way back in — @laserstack_sdb was lost because none of them was
written down.

## Why not the official API

X removed the free API tier on 2026-02-06. Access is pay per use, from prepaid
credits in the Developer Console:

| Action | Price |
|---|---|
| Post | $0.015 |
| Post with a link | $0.200 |
| Read one post | $0.005 |

The link surcharge is 13 times the price of a plain post, and most posts of this
project carry a link: 300 link posts a month cost $60. `twitter-cli` sends the
same GraphQL requests as the web app, with the cookie of the account, so a post
costs nothing.

## Risk

Automating a web session is against the X terms of service. X can rate-limit,
lock or suspend the account. That is why the project has its own handle: the
damage stops at @laserstackphp and never reaches the personal account.

Keep the account within human behavior: a few posts, no bulk follow or unfollow,
no direct messages, no bursts. An unverified account may create about 50 posts
and 200 replies a day, inside a 30-minute burst window that X does not publish.

The cookie is a password. `auth_token` gives full control of the account until
that session ends.

## Create the account, once

1. In Chrome, open the profile menu, choose **Add**, and make a profile named
   `laserstackphp`. Sign in to x.com as this account only, in that profile.
2. Sign up at <https://x.com/i/flow/signup> with `laserstack@bruder.com.br`.
   Open the 1Password item, copy the generated password and paste it.
3. Click the verification link that arrives at the alias.
4. Two-factor: **Settings** → **Security and account access** → **Security** →
   **Two-factor authentication** → **Authentication app**. Show the QR code and
   add it to the item's **one-time password** field. Do not choose SMS: the
   phone number is the part that goes stale.
5. **Settings** → **Two-factor authentication** → **Recovery code**. Save the
   codes in the notes of the item.

## Store the cookie, once

1. In that browser, open <https://x.com>, then DevTools (⌥⌘I) → **Application** →
   **Cookies** → `https://x.com`.
2. Copy the values of `auth_token` and `ct0`.
3. In the 1Password item, add two **text** fields named exactly `auth_token` and
   `ct0`, and paste the values. The names are what `tools/x` reads; a different
   name reads as an empty cookie.

Check both, then the account:

```sh
op read 'op://Private/Laser Stack X/auth_token' | wc -c   # not 0
tools/x whoami                                            # @laserstackphp
```

## Install, once

```sh
uv tool install twitter-cli
```

Then turn on **1Password** → **Settings** → **Developer** → **Connect with
1Password CLI**, so `op read` answers without a separate sign-in. Run
`uv tool upgrade twitter-cli` when a request starts to fail: X changes the web
app often, and the tool follows it.

## Use

```sh
tools/x whoami                          # must print @laserstackphp
tools/x post "Laser Stack 2.0 is out"    # a post
tools/x post "text" -i docs/og.png       # with an image, up to four
tools/x reply <tweet-id> "text"
tools/x quote <tweet-id> "text"
tools/x delete <tweet-id>
tools/x feed --max 20                    # home timeline of that account
tools/x user-posts laserstackphp --max 20
tools/x search "laserstack" -t Latest
```

Add `--json` or `--yaml` for scripts. `twitter --help` lists every command;
`tools/x` passes all of them through.

`tools/x` looks for the cookie in this order: `TWITTER_AUTH_TOKEN` and
`TWITTER_CT0` in the environment, then the 1Password item, then a file at
`~/.config/laserstack/x.env` (mode 600, `TWITTER_AUTH_TOKEN=...` lines). The
file exists for a machine without 1Password. When none of the three answers, the
wrapper stops instead of letting `twitter-cli` extract the cookies of whichever
browser it finds.

## When it breaks

| Message | Cause | Fix |
|---|---|---|
| `Cookie expired or invalid (HTTP 401)` | the session ended | repeat **Store the cookie** |
| `Couldn't get KEY_BYTE indices`, or a transaction-id error | X changed its web app | `uv tool upgrade twitter-cli` |
| `no cookie in op://Private/...` | vault locked, wrong field names, or 1Password CLI not connected | `op read 'op://Private/Laser Stack X/ct0'` must print a value |
| a post gone out from the wrong account | never possible here: the cookie names the account | `tools/x whoami` |

## If the account is lost again

1. **Password**: <https://x.com/i/flow/password_reset>, enter `laserstackphp`,
   use the link that arrives at `laserstack@bruder.com.br`, then choose
   **Try another way / Use email instead** if login asks for a phone.
2. **TOTP**: the seed is in the item. **Codes**: in the notes.
3. A live browser session still works while its cookie lives: copy `auth_token`
   and `ct0` from DevTools and skip the reset entirely.
