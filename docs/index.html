Many PHP projects.
One small stack.

Laser Stack serves all of your Laravel, Symfony and WordPress projects from a single set of Alpine containers — one nginx, one PHP-FPM per version, one database server. No VM, no per-project containers, no dashboard application to install.

A PHP version per project

A project states the PHP it needs in a .laserstack file — laser use php 8.5 writes it — and the stack starts one php-fpm worker for that version: the same image, no nginx of its own and no published port. 7.4 to 8.6.

PHP_VERSION=8.4
MYSQL_VERSION=8.4
POSTGRES_VERSION=18
PROFILES=mysql,redis

Versions are variables

PHP_VERSION, MYSQL_VERSION, MARIADB_VERSION, POSTGRES_VERSION, REDIS_VERSION and the rest select the image tag and the matching config directory. Two checkouts can run different versions from the same repository.

config/
├─php84/php.ini
├─nginx/http.d/
├─mysql/8.4/docker.cnf
└─postgres/18/

Config lives in git

php.ini, php-fpm, nginx and every database config are files of this repository, one directory per version. Change a value, restart one service, keep the change in a commit.

$laser artisan migrate
$laser npm run dev
$laser mysql
$laser logs app --tail 50

A CLI, not a GUI

laser exposes every docker-compose command unchanged and adds the ones you type all day: artisan, composer, php, npm, shell, mysql, psql, share, scan.

04 · Platforms

Your machine, your docker.

Official support for the three environments developers use, with any docker that speaks compose v2 — and nothing installed on the host besides it.

macOS

  • Docker Desktop, OrbStack or Colima
  • Intel and Apple silicon
  • The numbers on this site come from an M3 with OrbStack

Linux

  • docker engine with the compose v2 plugin
  • No desktop app, no VM
  • The same script, the same compose file

WSL2 / WSLg

  • Docker Desktop with the WSL2 backend
  • Keep projects in the Linux filesystem (~/src), not under /mnt/c
  • Bind mounts and file watching stay fast

No VM of its own, no system package, no shell profile, no daemon: laser is a bash script and docker does the rest. The installer checks bash, git and docker with compose v2 before it clones anything.

05 · Frameworks

Laravel, Symfony, WordPress, or your own.

laser scan asks each driver what a project is and writes its vhost: the Laravel, Symfony, WordPress and generic drivers are in libs/.

LaravelSymfonyWordPressgenericown nginx config

Each project gets one vhost for project.SUFFIX, serving its public/ directory. A project that needs something else ships a laserstack-nginx.conf in its root and the generic driver installs it. Nothing is generated into your checkout.

07 · FAQ

Questions before you start.

Is Laser Stack free?

Yes. It is open source under the BSD-3-Clause license. There is no account, no paid tier and no telemetry.

Do I need Docker?

Yes: any docker with compose v2 — Docker Desktop, OrbStack, Colima or the engine. The stack installs nothing else on the host: no VM, no system package, no daemon of its own.

Does it run on Windows?

Through WSL2/WSLg, with Docker Desktop and the WSL2 backend. There is no native Windows version.

Can two projects use different PHP versions?

Yes. A project states the version in .laserstack, and the stack starts one php-fpm worker for that version next to the app container. 7.4 to 8.6. The database is still one version per engine.

Do I need a hosts file?

No for the default suffix: every name under localdev.it already resolves to 127.0.0.1 and ::1 for anyone. A suffix of your own needs /etc/hosts; a dnsmasq that laser installs and maintains is on the roadmap.

How does https work?

With the default suffix, laser up fetches the published wildcard certificate of *.localdev.it, which every browser already trusts, so there is no CA to install and no warning page. With a suffix of your own, laser tls creates a CA and a certificate, and laser trust puts the CA where the platform reads it; laser trust --remove takes it out.

Does it work with Symfony, WordPress or plain PHP?

Yes. The Laravel, Symfony, WordPress and generic drivers find the document root on their own, and any project can ship its own laserstack-nginx.conf.

Is there a GUI?

No desktop application, and none is planned. The CLI is the interface. The stack serves a read-only dashboard for itself on laserstack.<SUFFIX>, with the PHP series, the projects, the services and the certificate, and laser dashboard opens it. See what it shows.

One command. Then two.

The clone belongs next to your projects, because that directory is what the stack mounts and serves.

curl -fsSL https://localdev.it/laserstack/install | bash

$ cd ~/src/laserstack && laser up -d
$ laser scan
# projecta.localdev.it and projectb.localdev.it answer
